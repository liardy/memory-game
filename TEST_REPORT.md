## 4. Найденные дефекты

### BUG-01. В 8 раунде нет бонусов, хотя конфиг задаёт 5 бонусов

| Поле | Значение |
| --- | --- |
| Приоритет | P1 |
| Статус | Reproducible |
| Область | `colorMatch`, бонусы |
| Файл | `src/App.tsx` |
| Строки | около 379-399 |

Шаги:

1. Дойти до 8 раунда.
2. Посмотреть левую панель бонусов.

Фактический результат:

В левой панели отображается «Нет бонусов».

Ожидаемый результат:

На 8 раунде должно быть 5 доступных бонусов согласно `LEVELS` и описанию игры.

Вероятная причина:

Для `colorMatch` все пары создаются как `8️⃣`, но в `EMOJI_BONUS_MAP` нет бонуса для `8️⃣`. Из-за этого `bonusMap` остаётся пустым.

### BUG-02. В 8 раунде дублируются ключи ловушек, после перехода на 9 раунд остаётся лишняя ловушка `8️⃣`

| Поле | Значение |
| --- | --- |
| Приоритет | P1 |
| Статус | Reproducible |
| Область | `colorMatch`, панель ловушек, React rendering |
| Файл | `src/App.tsx` |
| Строки | около 398-399 и 1387-1393 |

Шаги:

1. Дойти до 8 раунда.
2. Перейти на 9 раунд.
3. Посмотреть правую панель ловушек и консоль браузера.

Фактический результат:

В консоли есть предупреждения React:

`Encountered two children with the same key, 8️⃣`

На 9 раунде в панели ловушек отображается лишняя строка `8️⃣`, хотя в 9 раунде должны быть только 3 ловушки.

Ожидаемый результат:

Ключи строк должны быть уникальными, а панель ловушек должна полностью соответствовать текущему раунду.

Вероятная причина:

В `colorMatch` массив `selectedEmojis` состоит из одинаковых `8️⃣`, поэтому `trapEmojis` может получить одинаковые значения. При рендере используется `key={emoji}`, что не уникально.

### BUG-03. Узкое окно браузера ломает компоновку: часть UI уходит за экран

| Поле | Значение |
| --- | --- |
| Приоритет | P1/P2 |
| Статус | Reproducible |
| Область | UI/adaptive layout |
| Файлы | `src/App.tsx`, `src/components/ScorePanel.tsx` |

Шаги:

1. Открыть игру в узком окне около 400px шириной.
2. Посмотреть верхнюю панель, поле, панели бонусов и ловушек.
3. Нажать элементы справа в верхней панели.

Фактический результат:

Часть заголовка, таймера, кнопок, боковых панелей и игрового поля обрезается. После взаимодействия с правой частью верхней панели видимая область фактически показывает другую часть широкого layout, а левая часть поля уходит за экран.

Ожидаемый результат:

Интерфейс должен адаптироваться: верхняя панель и поле должны быть видимыми и управляемыми без потери важных элементов.

Комментарий:

Если мобильная/узкая ширина не поддерживается продуктово, это нужно явно зафиксировать в требованиях. Сейчас страница выглядит доступной, но часть управления фактически скрыта.

3. Добавить уникальный `pairId` или `cardTypeId` в `GameCard` и использовать его для бонусов, ловушек, совпадений и React keys.
4. Решить продуктово, поддерживается ли узкая ширина. Если да, переработать layout: верхнюю панель и боковые панели нужно складывать или делать доступными без обрезки.
